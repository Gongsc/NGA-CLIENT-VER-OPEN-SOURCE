# 首页版块收藏同步

## 原因

首页原有“我的收藏”仅从 `BOOKMARK_BOARD` 本机偏好数据恢复版块。登录后的首页刷新只更新账号显示，并未请求论坛收藏，因此重新安装或更换设备后无法看到论坛端已收藏的版块。

## 实现

版块收藏统一调用 `nuke.php?__lib=forum_favor2&__act=forum_favor&__output=8`，读取使用 `action=get`；收藏和取消收藏分别使用 `action=add`、`action=del`，编号放入 `fid` 字段，合集优先使用 `stid` 的值。接口依据 [MNGA 的版块收藏实现](https://github.com/BugenZhao/MNGA/blob/main/logic/service/src/forum.rs)确认，并按本项目现有 Retrofit、Cookie 和 Compose 结构独立实现。

请求使用发起时的当前账号 Cookie，遵循响应编码声明，缺失声明时采用 GB18030。解析同时支持对象和数组集合、字符串编号、负数版块编号与合集编号；业务错误或不完整响应不会被视为空收藏。

同步结果按账号存入应用私有偏好数据。账号或登录会话变化时取消旧请求，并通过请求代次检查拒绝过期结果。失败保留原缓存；明确的成功空集合仅清空当前账号的论坛收藏缓存。自动请求在成功后设置 60 秒间隔，手动同步可立即发起请求。

首页仅展示论坛收藏，可进入原有原生版块列表。旧本机收藏存储不再加载或写入，其排序、清空和迁移逻辑已移除。版块菜单、按编号添加及首页取消收藏共用论坛收藏仓库，并在服务端确认成功后更新状态及缓存。写入期间阻止重复提交和读取结果覆盖，失败不会显示虚假的成功状态。

首页取消收藏需要确认。未登录时引导登录；账号切换后不应用旧账号请求结果。首页与版块菜单订阅同一状态，收藏完成后无需重启应用。

## 验证

- 单元测试覆盖接口数据结构、空集合、业务错误、不完整数据、编号与合集去重、缓存序列化、账号切换、旧请求结果、退出登录、失败重试及自动请求间隔、收藏写入确认、取消失败、重复提交阻断及写入期间的账号切换。
- Compose 设备测试覆盖未登录时的登录同步入口、论坛收藏原生导航、旧本机收藏隐藏、论坛收藏取消入口、版块菜单等待状态、缓存保留、同步错误显示及加载期间防止重复请求。
- 使用截获请求的模拟传输验证收藏和取消收藏的真实 Retrofit 请求方法、Cookie、论坛接口、动作及合集编号，未向模拟目标发出网络请求。
- 已在已连接的 Android 16 设备上确认真实账号的论坛收藏能够自动读取并显示。实机验证保留既有论坛收藏，写入与故障路径通过固定响应测试验证。
