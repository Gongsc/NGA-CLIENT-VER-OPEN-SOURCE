# 主题打开与浏览器跳转修复

## 问题原因

旧详情加载逻辑将无法解析的响应视为服务端异常，随后尝试其他账号；失败后默认启动内置浏览器，并关闭当前详情页。该行为使主题阅读被页面跳转中断。

正文链接采用固定字符串前缀识别。相对地址、协议相对地址及未正确匹配的域名会落入外部浏览器分支。域名资源中 `nga.178.com` 末尾还包含多余引号，影响该域名的请求与链接识别。原主题入口的整数参数解析也会因 URL 片段而失败。

## 调整内容

- 移除解析失败后的自动浏览器跳转、页面关闭及备用账号请求，同时删除对应的自动跳转设置。
- 主题请求采用兼容的 User-Agent、X-User-Agent 与 Referer。请求开始时固定当前账号 Cookie，格式重试保留主题、回复、分页及作者筛选参数。
- 将读取来源与正文转换分离，依次尝试 JSON、普通网页、XML 与备用 XML，最多四次请求。同一来源不重复请求；业务错误及网络错误直接反馈。
- 将 XML 数据转换为既有详情数据结构，处理索引集合、用户映射、字符串计数、CDATA 与编码。拒绝 DTD 和外部实体，避免 XML 解析访问额外资源。
- 正文链接通过 URL 解析器识别实际域名与路径。NGA 主题和版块进入应用内页面；图片与用户资料使用各自入口。外部网页仍响应用户主动打开操作，子框架导航不启动页面。
- 主题入口通过结构化查询参数读取主题编号、回复编号、页码、作者编号及回复检索标识，避免片段或参数名子串影响解析。
- 保留详情菜单中的手动浏览器入口。接口不兼容、账号权限及网络可用性仍由服务端与运行环境决定，应用不绕过权限或访问限制。

## 验证范围

单元测试使用固定响应验证兼容格式切换、四种来源的请求上限、账号与参数保留、业务及网络错误、UTF-8 与 GB18030、旧 JSON 数字文本、XML 用户映射和外部实体拒绝，并验证链接别名、相对路径、分页片段、伪造域名及非网页协议。

Android 设备测试验证 WebView 显式导航、外部网页入口、子框架处理、XML 到原生详情数据的完整转换，以及解析错误后详情页保留错误与重试入口。上述测试不提交真实内容，也不替代测试账号下的线上认证与权限验证。

## 不完整响应处理

针对 [主题 47787244](https://bbs.nga.cn/read.php?tid=47787244) 排查时，观察到 XML 响应在楼层字段中途结束；手机登录状态下也出现 JSON/XML 解析失败，后续完整响应能够正常转换。网页可访问并不保证同一时刻接口返回的文档完整。

加载器在解析前检查 JSON 字符串、括号结构与 XML 根元素是否完整。不完整的数据不进入正文转换或缓存。此前额外重取相同接口的方案已由统一来源切换替代。

## 统一主题解析

针对 [主题 47787820](https://bbs.nga.cn/read.php?tid=47787820) 的在线排查确认：JSON、XML 与备用 XML 均可能在楼层字段中途结束，而普通网页包含完整楼层。单纯切换接口格式或重复请求不能解决这种情况。

现有实现按以下顺序读取，每个来源至多请求一次：JSON → 普通网页 → XML → 备用 XML。后续来源沿用当前账号、主题、回复、页码和作者筛选参数，并使用独立查询标记及禁止缓存的请求头。权限错误、论坛业务错误和网络错误不进入其他来源；应用不自动切换账号或打开浏览器。

网页解析器通过 jsoup 读取文档，从启动数据中提取主题、用户、楼层编号、回复编号、时间、评分和客户端标识，从正文节点提取楼层内容，并保留附件及编辑提示。脚本参数使用支持引号、转义和嵌套括号的扫描器读取，不执行网页 JavaScript。正文进行 HTML 清理，整页导航、广告和事件处理脚本不进入阅读内容。

各来源统一转换为 `__T`、`__R`、`__U` 和分页计数结构，校验请求主题、楼层数量和必要字段后，交由现有正文转换及缓存流程处理。网页末尾、楼层结束标记、正文与元数据必须匹配，避免将未结束的网页或遗漏楼层误认为完整页面。删除的楼层保留编号间隔，不生成虚假内容；作者筛选以网页分页信息为准。GBK、GB2312 标头使用 GB18030 超集解码，正文转换层不再重复修补原始 JSON。

自动测试采用合成数据，覆盖多来源切换、截断响应、嵌套脚本参数、正文清理、附件、编辑提示、分页、权限错误、主题编号及楼层计数校验、原生正文转换和缓存读取。真实主题与账号数据未纳入测试资源。在线响应验证覆盖两个异常主题，以及主题 47787820 的第二页；Android 模拟器临时在线测试同时验证了实际网络读取与原生楼层转换，另以首个接口响应合成截断的方式，强制走普通网页来源，三个页面均在第二次请求完成实际网页到原生正文的转换。临时测试组件未安装到用户手机，验证后已移除。

网页路径基于当前 NGA 页面结构；若服务端改变文档结构，仍可能需要适配。网页投票及特殊嵌入内容未在本次两个异常主题中覆盖验证。

参考了 [MNGA 的网页归一化处理](https://github.com/BugenZhao/MNGA/blob/main/logic/service/src/topic/web_to_xml.rs)与 [SNGA 的主题解析器](https://github.com/Gongsc/SNGA/blob/main/SNGA/Network/NGAParser.swift)。本仓库依据观察到的响应结构独立实现 Java 解析器，未复制参考项目代码。

## 热点回复数据

JSON、XML 响应读取主楼 `hotreply` 集合，按索引顺序转换为独立热点列表，并校验回复编号、去除重复条目。单个异常热点不影响主楼及正常回复。热点数据不改变 `__ROWS` 与正常楼层列表，缓存仍保存统一原始数据。

网页解析区分正常数字楼层参数与内嵌回复参数，从 `hightlight_for_0` 中提取热点正文、作者、时间、评分及客户端信息。原楼层号优先从同页正常回复匹配；无法确定时不显示虚假的楼层号。包含热点的网页不会再因内嵌回复参数不是数字而解析失败。

使用合成响应验证解析、缓存、去重和异常条目隔离。临时在线测试验证主题 47787820 的 JSON 与强制网页来源均生成独立热点列表；界面测试覆盖热点位置、引用目标、正常楼层跳转、四种主题的浅深背景，以及大字体、小屏和横屏下的可操作性。
