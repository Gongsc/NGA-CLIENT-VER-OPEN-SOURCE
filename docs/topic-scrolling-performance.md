# 主题滚动性能记录

## 排查结果

旧实现为每个楼层创建 WebView，即使该楼层仅含普通短回复。正文视图未启用 AndroidView 的列表复用路径，滚出可见区域后销毁，再次出现时重新创建和加载文档。初始高度固定为 48 dp，离屏重建后重新测量，可能使列表的内容高度再次变化。

高度测量脚本在页面加载进度达到 100 时安装 ResizeObserver 和图片加载监听，缺少安装去重及尺寸去重，可能增加脚本通知、主线程回调和布局开销。

## 调整

- 无图片、链接、BBCode、复杂 HTML 和附加内容的文字回复使用 Compose Text。保留 HTML 实体和换行；屏蔽、隐藏、引用、附件、投票、编辑提示及可见签名继续使用原富文本路径。
- 富文本 AndroidView 启用 onReset，复用正文容器；绑定时更新回调与图片集合，释放时销毁。列表使用楼层身份及统一内容类型标识。
- 楼层正文高度使用可保存状态，避免离屏后回到固定占位高度。
- 尺寸观察器按文档去重，合并短时间内的通知，并在脚本和原生侧过滤相同尺寸。通知携带文档代号，复用后的旧通知不能更新新楼层高度。宽度变化时重新测量。

## 验证

单元测试覆盖普通文字与富文本分流条件。Android 测试覆盖长正文不裁切、容器切换长短正文后的高度归属、往返滚动时容器复用，以及实体与换行转换。现有主题换色、图片地址、正文导航和详情交互测试同时通过。

在连接的 Xiaomi 13 上，以主题 47786601 进行八次相同坐标、450 ms 时长的上下滑动，使用系统 gfxinfo 采样。原实现记录 1044 帧，帧耗时 P95 为 26 ms、P99 为 73 ms；最终版本预热后的抽样记录 1146 帧，P95 为 18 ms、P99 为 48 ms。仅启用容器复用的首轮样本未显示改善，因此继续实施普通回复原生排版。

这些数据来自调试构建的人工设备排查，缓存、网络、温度、初始位置、正文高度变化及显示刷新率均可能影响结果；样本帧数也不一致，不作为严格基准或固定提升比例。预热后的结果不能代表图片或富文本首次加载性能，复杂富文本仍有 WebView 渲染开销。

## 后续字号与布局调整

普通回复原生排版后曾直接使用 24 sp，而富文本沿用正文 70% 的网页缩放，形成基础字号差异。现已共用“基础字号 × 正文缩放”设置；原生文字使用 sp，网页按同一 Compose 密度与字体缩放规则转换为 CSS 像素，并关闭额外 textZoom。系统大字体可能采用非线性换算，验证以实际 Compose 字号换算结果为准，而非简单乘以 fontScale。

字号变更监听与 PhoneConfiguration 使用相同的默认偏好设置来源，确保设置修改即时生效。设备测试覆盖 70%、90% 阅读缩放，以及 1.0、1.5、2.0 系统字体缩放，比较原生排版字号与网页计算字号，并检查卡片左右 8 dp 边距。楼层背景调整为 14 dp 圆角，热点容器保留其主题颜色。上述性能抽样来自此前构建，不作为后续字体及卡片调整的固定性能结论。
